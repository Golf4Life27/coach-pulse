# Plain-Language Reporting — the AKB communication standard

Alex's instructions were getting lost in jargon and it stalled the build.
This is the standard for every report, in every session. Installed
2026-08-26 by operator directive (Wholesale OS Critical Fixes).

## The seven rules

1. **Plain language.** Say what a thing does, not what it's called. "The
   reply reader," not the scenario name. If an identifier is needed to
   find something, put it in parentheses once or in a lookup note at the
   end. Never in the story.
2. **Every report opens with the scoreboard line:** live conversations ·
   sellers who have named a number · how many of those fit our ceiling ·
   total fee if they close · what's blocking the closest one. Real
   numbers, or "not measured." Never an estimate dressed as a fact.
3. **Then: what's wrong, what you did about it — in that order.** When
   several things fail the same way, name the shared cause once. Don't
   list each case.
4. **Decisions for Alex: as few as possible**, each with a recommended
   default, phrased so he can answer yes or no.
5. **Revenue reports carry revenue only.** Housekeeping goes in a short
   section at the bottom or gets left out. Never bring up other projects
   (AuditOps, golf work, the tool site) unless Alex does.
6. **Length: one to two phone screens.** If it must be longer, the first
   screen has to stand alone.
7. **Read the system's state before asking Alex anything.** Never make
   him re-explain what's already recorded.

## End-of-session report order

1. Scoreboard line
2. What's fixed, what's drafted for approval
3. Decisions for Alex, each with a default
4. What you didn't do and why
5. Next session's first task
